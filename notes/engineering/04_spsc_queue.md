# 04｜SPSC 环形队列：让生产者和消费者分别修改一个位置下标

> 复习主线：生产者只修改写入位置，消费者只修改读取位置；先写完再让对方读取，先读完再让对方覆盖。

## 面试题目（提供给候选人）

SPSC 是 Single Producer, Single Consumer 的缩写，即单生产者、单消费者。实现这种固定容量的环形队列，元素为 uint64_t；满或空立即返回 false，不阻塞。数组中每个存放元素的位置称为槽位。说明为什么槽位中的数据可以使用普通整数，而位置下标需要使用原子变量。

- 建议 30 分钟；考察每个共享变量由谁修改、跨线程读取数据的顺序，以及一个线程暂停时其他线程能否继续操作。
- 底层 N 个槽位，N≥2，可用容量 N−1；不允许第二个生产者或消费者。
- 仅实现 try_push/try_pop，不要求多生产者多消费者（MPMC）、动态扩容和动态节点释放。

## 面试官答案：先用一个空位区分满与空

```text
head：下一次读取的位置，只由消费者推进
tail：下一次写入的位置，只由生产者推进
head == tail          → 空
next(tail) == head    → 满
```

留一个空位省掉双方共同修改的 size 计数。每个索引只有一个写者，所以更新自己的下标不需要“比较并交换”（CAS：仅当当前值等于预期值时才更新）。但下标也会被另一个线程读取，因此仍要使用 `std::atomic`，避免数据竞争。

### 必须保证写完后才能读、读完后才能覆盖

**第一条：生产者先把数据写入数组，再更新 tail，告诉消费者这份数据可以读取了。**

📌 代码依据：[SpscQueue::try_push](../../engineering/concurrency/04_spsc_queue.cpp)：

```cpp
if (next == head_.load(std::memory_order_acquire)) {
  return false;
}
data_[tail] = value;
tail_.store(next, std::memory_order_release);
```

**第二条：消费者先从数组读完数据，再更新 head，告诉生产者这个位置可以重新写入了。**

📌 同文件 `SpscQueue::try_pop`：

```cpp
if (head == tail_.load(std::memory_order_acquire)) {
  return false;
}
value = data_[head];
head_.store((head + 1) % N, std::memory_order_release);
```

这里使用 C++11 的内存序（memory order）规定跨线程访问的顺序。生产者写完数据后，用 release 操作更新 tail；消费者用 acquire 操作读到这个更新后，才能读取之前写好的数据。head 的更新用同样的方法保证消费者读完之后生产者才覆盖。

这就是本题中 release/acquire 配对的用途。读取只有自己会修改的下标时，使用 relaxed 即可：仍是原子读取，但不需要借它建立与另一个线程的同步。读取对方下标时如果暂时读到旧值，可能暂时把队列判断为满或空并返回 false，但不会因此读到未写好的元素，或覆盖未读完的元素。

## 正确性、复杂度与无锁保证

每次 try 操作在算法中只执行固定数量的步骤，时间 O(1)，存储 O(N)。元素采用固定大小的整数，使核心实现不涉及动态分配和复杂对象的构造、移动。

讨论并发算法时要区分两个术语：**lock-free（无锁）**保证某个线程暂停不会阻止所有其他线程完成操作，但单个线程可能不断重试；**wait-free（无等待）**进一步要求每次调用都能在有限且有上限的自身执行步骤内结束。这里的“结束”也包括 try_push/try_pop 返回失败，并不保证一定入队或出队成功。测试中的 while/yield 会不断重试直到成功，不能把这个外层循环称为 wait-free。

示例打印下标原子变量的 `is_lock_free()`，检查当前平台是否用无锁方式实现这种原子操作。虽然 try 函数本身没有重试循环，如果底层原子操作内部需要加锁，就不能声称整体实现无锁。即使检测结果为无锁，也不能据此保证每次原子操作都满足 wait-free，或保证线程在多少微秒内被调度执行。

CPU 通常按缓存行（一段连续内存）维护缓存一致性。如果 head 和 tail 在同一缓存行，不同 CPU 核心虽然修改不同变量，也可能反复让对方的缓存副本失效，这叫**伪共享（false sharing）**。它影响速度，不改变上述正确性。示例不为了优化而写死缓存行大小；若要把变量分别放入独立缓存行，还需处理不同平台和 C++11 动态内存对齐的限制。[Boost SPSC 文档](https://www.boost.org/doc/libs/1_92_0/doc/html/lockfree.html)可对照单生产者/单消费者约束与 lock-free/wait-free 的说明。

## 分层追问与参考答案

- **基础：把所有内存序改成 relaxed 会怎样？** 无法保证写数据、读数据、覆盖数据的跨线程先后关系（C++ 内存模型中称为 happens-before），普通数组元素可能出现数据竞争；不能只凭某台机器测试正常判断安全。
- **资深：两生产者为什么不行？** 它们可能同时拿到同一 tail 并写同一槽位。给 tail 随便加 CAS 还不够，必须区分“某生产者已预留这个位置”和“这个位置的数据已写好”，否则消费者可能读取尚未写完的数据。
- **资深：CAS 能发现变量中途被修改过吗？** 不一定。值经历 A→B→A 后，CAS 仍可能认为它等于原来的 A，这就是 ABA 问题。例如一个节点被删除后，相同地址又分配给新节点。需要结合版本号和节点释放方式分析，不能只看比较是否成功。
- **专家：链式 MPMC 如何安全释放节点？** hazard pointer（危险指针）让线程登记自己正在访问的节点，其他线程暂时不能释放它；epoch（按访问阶段延迟回收）等所有可能持有旧节点的线程结束相应访问后，再释放节点。还要考虑线程长时间不结束访问、线程退出，以及因此积压的内存。此静态数组不删除节点，但不能由此推断其他队列无需回收。
- **专家：有 CAS 的有界 MPMC 必然 lock-free 吗？** 不必然；若某线程占了序号后停顿，其他线程可能等待该槽位发布。必须分析一个线程暂停时其他线程是否仍能完成操作，不能只看是否用了互斥锁。

## 评分与验证

基础达标为满空与环绕正确；资深达标需解释数据写入、读取、再次覆盖的顺序如何保证；专家加分看是否区分预留位置、完成写入和释放节点。提示“读完后才能覆盖”才为 head 添加 release 操作，应记录为提示后修复；坚持使用普通变量保存跨线程下标，或直接把本实现用于 MPMC，属于严重错误。

运行 `make run eng_spsc_queue`：容量 1 的边界、反复环绕、10 万条跨线程顺序与不丢不重。压力测试和 ThreadSanitizer（TSan，运行时数据竞争检测工具）只能检查实际执行过的情况，不能代替对所有可能执行顺序的分析。
