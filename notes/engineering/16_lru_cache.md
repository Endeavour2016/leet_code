# 16｜LRU Cache：淘汰最久未使用的条目

> 复习主线：哈希表负责快速找到节点，双向链表负责维护使用顺序；访问成功和更新都移到表头，容量满时删除表尾。

## 面试题目（提供给候选人）

LRU（Least Recently Used，最近最少使用）缓存只保留有限数量的键值对。缓存满后再写入新键，需要淘汰最久未使用的条目。实现一个 C++11 `LruCache`，键和值均为 `int`，容量 `capacity` 为 `std::size_t`，按条目数计算。

建议用时 30 分钟：5 分钟澄清接口和例子，20 分钟实现，5 分钟验证与解释。

| 接口 | 输入、输出与限制 |
|---|---|
| `explicit LruCache(std::size_t capacity)` | 固定容量；0 表示禁用缓存。调用者不能把负数转换成容量传入 |
| `bool Get(int key, int& output)` | 命中返回 true，写入值并刷新使用顺序；未命中返回 false，输出和缓存均不改变 |
| `bool Put(int key, int value)` | 插入或更新成功返回 true；更新也刷新顺序；容量为 0 时返回 false 且保持状态 |
| `std::size_t size() const` | 返回当前条目数，不改变顺序 |

要求查询、写入平均 O(1)，空间 O(capacity)。全部 `int` 值都合法，包括 -1，因此不能用 -1 表示未命中。只要求单线程或外部串行访问，不实现过期时间、持久化、容量调整或按字节计费。不使用异常；内存分配失败不在本题恢复范围内。复制与移动可明确禁止。

容量为 2 的例子：

| 操作 | 结果 | 缓存顺序：最近使用 → 最久未使用 |
|---|---|---|
| `Put(1, 10)` | true | `1:10` |
| `Put(2, 20)` | true | `2:20 → 1:10` |
| `Get(1, value)` | true，value = 10 | `1:10 → 2:20` |
| `Put(3, 30)` | true，淘汰 2 | `3:30 → 1:10` |
| `Get(2, value)` | false，value 仍为 10 | `3:30 → 1:10` |
| `Put(1, 100)` | true，更新 1 | `1:100 → 3:30` |
| `Put(4, 40)` | true，淘汰 3 | `4:40 → 1:100` |

## 面试官参考答案

### 为什么使用两个容器

只用数组可以顺序查找和移动元素，但每次操作可能需要 O(n)。只用哈希表能快速找到值，却不知道哪个条目最久未使用。手写双向链表也可达到要求，但需要自行处理节点分配、删除和前后指针。

参考实现使用 `std::list<std::pair<int, int> >` 保存键值对，再用 `std::unordered_map<int, EntryList::iterator>` 保存每个键对应的链表迭代器。链表表头表示最近使用，表尾表示最久未使用。链表节点必须同时保存键，因为淘汰表尾时还要根据键删除哈希表记录。

完整实现与验证见 [16_lru_cache.cpp](../../engineering/cache/16_lru_cache.cpp)，前半部分是缓存类，后半部分是测试。

### 查询、更新与淘汰

1. **Get**：在哈希表中查找。未命中直接返回 false；命中后移动节点到表头，再复制值到输出。
2. **Put 已有键**：更新节点中的值并移动到表头，不增加条目数，也不淘汰其他键。
3. **Put 新键**：先处理容量为 0 的情况；容量已满时，先删除表尾键的哈希记录，再删除链表节点；随后在表头插入新节点，并建立哈希映射。

移动节点的关键代码是：

```cpp
entries_.splice(entries_.begin(), entries_, found->second);
```

同一链表内移动一个节点不复制键值，也不会使指向它的迭代器失效，因此哈希表中的迭代器不需要更新。节点已经在表头时同样适用。若用“删除旧节点、重新插入”代替移动，却忘了更新映射，后续查询就会访问已经销毁的节点。

### 正确性：每一步必须维持什么

- 每个键在链表和哈希表中各出现一次，哈希表指向对应的有效节点。
- 链表按最后一次成功 Get 或 Put 的先后排列，最近使用的在前。
- 操作完成后，条目数不超过容量。

初始状态为空，三条条件都成立。命中或更新只把当前节点移到最前，其余节点相对顺序不变；未命中不改变顺序。插入新键时，它成为最近使用的节点；若已满，表尾恰好是所有条目中最久未使用的节点，删除它再插入即可维持容量和顺序。

例如容量为 2，依次写入 1、2，再更新 1 后写入 3，正确淘汰对象是 2。若更新只改值而不移动节点，就会错误淘汰 1。若先按容量淘汰再判断是否是已有键，还可能让一次更新意外删除另一条记录。

### 复杂度与使用限制

设当前缓存条目数为 n。链表移动、表头插入与表尾删除均为 O(1)；哈希查找、插入、删除在通常哈希假设下平均 O(1)，插入的扩容成本按多次操作摊销，极端碰撞下单次操作可能 O(n)。因此 Get/Put 是平均 O(1)，不是严格最坏 O(1)。`size()` 为 O(1)，两个容器合计空间 O(n)，上界为 O(capacity)。

实现不预先按容量分配全部空间。`Put` 的 false 只表示容量为 0，不代表分配失败能恢复；禁用异常不会让标准容器把内存不足转换成 bool。示例也不承诺资源失败后继续运行。

Get 会修改链表，因此同一个缓存上的两个 Get 也不能无同步地并发执行；多线程使用时需在外部对所有访问串行化，包括与写入并发的 `size()`。输出为值拷贝，避免向调用者暴露可能被淘汰的节点引用。

默认复制同样有风险：链表会复制成新节点，但哈希表中的迭代器仍指向原链表。参考实现显式删除复制与移动操作，以保持示例简单。若需要复制，必须复制链表后重新建立索引，不能只逐成员复制。

## 分层追问与参考答案

- **基础：容量为 0 或 1 时有什么陷阱？** 零容量必须在访问 `back()` 前拒绝写入，否则会访问空链表。容量为 1 时，更新同一键不能先删除该节点；插入不同键才淘汰。
- **基础：为什么不返回 -1 表示未命中？** -1 是合法缓存值。状态和值应分开返回；本题用 bool 加输出参数，未命中时保持输出。
- **资深：能给 Get 加读锁、Put 加写锁吗？** 不能直接这样做，因为 Get 命中也会修改链表。最简单的并发版本用一把互斥锁保护两个容器及整个操作，返回值在释放锁前复制好。回源加载慢数据应释放锁后执行，但还要另行定义重复加载和旧结果覆盖新值的问题。
- **资深：哈希表扩容会不会使链表迭代器失效？** 不会，映射中存的是另一个容器的链表迭代器。但扩容可能使哈希表自身的迭代器失效，不能在可能扩容的插入之后继续使用旧的哈希表迭代器。
- **资深：如何支持按字节限制容量？** 明确计费范围，保存每条记录的大小及总占用。新值过大时应在修改前拒绝；更新也要重新计算大小，必要时连续淘汰多条。还要处理整数溢出及失败时原数据是否保留，此时一次写入不再保证只淘汰一条。
- **专家：一次顺序扫描会怎样？** 假设容量为 2，原有两个频繁访问的键 A、B，随后扫描从不复用的 C、D，A、B 都会被淘汰。这叫缓存污染。可讨论访问第二次才准入、分段管理等策略，并用真实访问序列比较命中率和维护成本，不能只凭名称判断优劣。
- **专家：分片加锁是否保持全局 LRU？** 每个分片能维护自己的顺序，但通常不能保证全局最久未使用者被淘汰，也可能出现一个分片满、另一个分片空。应说明这是并发吞吐和全局淘汰精度的取舍。
