# Bitmap 三题：从精确集合到概率过滤

先学普通 Bitmap 的位操作，再看 Roaring 如何按局部密度节省空间，最后看 Bloom Filter 如何允许误判来缩小空间。三题都已有可编译的 C++11 简单实现，只使用标准库。

## 三者的关系

Bitmap 就是一串二进制位，通常放在 `std::vector<std::uint64_t>` 中。每个整数保存 64 位，置位、清位和查位是共同的基础操作，但三个结构对“一个位代表什么”的解释不同。

| 题目 | 一个位置代表什么 | 查询是否精确 | 节省空间的方式 | 简单实现 |
|---|---|---|---|---|
| [06 常规 Bitmap](06_bitmap.md) | 一个固定整数编号 | 精确 | 每个可能编号只占 1 位 | [Bitmap 类](../../engineering/common/bitmap.h) |
| [07 Roaring Bitmap](07_roaring_bitmap.md) | 稠密容器中，一个低 16 位编号 | 精确 | 按高 16 位分组；稀疏组用数组，稠密组用位图 | [RoaringBitmap 类](../../engineering/index/07_roaring_bitmap.cpp) |
| [08 Bloom Filter](08_bloom_filter.md) | 多个 key 可能共用的哈希位置 | 可能误报存在 | 把 key 映射到有限位数组，不保存原始 key | [BloomFilter 类](../../engineering/index/08_bloom_filter.cpp) |

因此不能把三者理解成“普通位图的三种压缩方式”：Roaring 是精确整数集合的混合表示，稀疏容器根本不需要展开成位图；Bloom 则放弃精确成员判断，把多个 key 的信息叠在同一张位图中。

## 用同一个小集合理解

假设集合为 `{1, 70, 65537}`。

- **普通 Bitmap**：直接设置第 1、70、65537 位。即使只有 3 个成员，也需要覆盖到编号 65537。
- **Roaring**：高 16 位为 0 的组保存 `[1, 70]`，高 16 位为 1 的组保存 `[1]`。两组都很稀疏，所以只用数组；若某组超过 4096 个成员，该组才转位图。
- **Bloom**：对每个 key 计算若干哈希位置并置位。查询一个没有插入的 key 时，它的位置也可能全部被其他 key 设置，因此“全为 1”只能表示可能存在。

常规 Bitmap 与 Roaring 可准确回答“70 是否在集合中”，Bloom 适合回答“是否可以确定这个 key 不存在”，用来减少后续昂贵的精确查询。

## 最小学习范围

1. **常规 Bitmap，20 分钟**：写出 set、reset、contains；用按位与、或解释交并集；算出空间为什么取决于编号范围。
2. **Roaring，30 分钟**：写出高低位拆分、有序数组插入和稠密转换；推导 4096 阈值；理解三种容器组合的交集。
3. **Bloom，25 分钟**：写出多位置置位和查询；用碰撞例子解释误判与不能直接删除。先理解给定位数 m、哈希次数 k 的流程，再读实现中根据 n、p 估算 m、k 的部分。

这一轮不要求并发、持久化、文件格式兼容、SIMD 或完整生产库。保留必要的越界判断与参数检查；三题都不恢复标准容器的内存分配失败。

## 运行与阅读

```bash
make run eng_bitmap
make run eng_roaring_bitmap
make run eng_bloom_filter
```

普通 Bitmap 的类定义在公共头文件，06 的 cpp 是测试入口；Roaring 和 Bloom 的 cpp 前半部分是实现，`main` 是验证区。阅读时先看类的核心方法，再用测试中的小例子走一遍。
