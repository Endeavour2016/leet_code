# 06｜Bitmap：用一个二进制位记录一个文档是否属于集合

> 复习主线：文档编号对应位图中的位置；按位运算完成集合运算。估算内存时，先看编号的取值范围，再看实际文档数。

## 面试题目（提供给候选人）

文档在索引中的整数编号称为 docID。为 docID 范围 `[0, U)` 实现位图（Bitmap），用 1 表示文档属于集合、0 表示不属于集合，支持设置、查询、清除、交集、并集、差集和计数。解释它适合什么检索过滤场景。

- 建议 20 分钟；考察数据布局、边界和集合运算。
- U 在构造时确定，存储在堆上动态分配，不要求在线 resize。
- set/reset 越界时返回 false；contains 对范围外编号返回 false。集合运算要求相同 U，不满足时返回 false 且不修改输出位图。U=0 合法。

## 面试官参考答案：两步定位，一条位运算

一个 uint64_t 数组元素包含 64 个二进制位，可以记录 64 个文档是否属于集合。docID 除以 64 得到数组下标，对 64 取余得到该元素内的位下标：

```text
docID 70 → 下标为 1 的数组元素→ 第 6 位
words[1] 的 bit 6 = 1 → 文档 70 属于这个集合
```

例如集合 `{1, 3, 6}`，按“第 7 位到第 0 位”书写为 `01001010`。设置 3 就与 `00001000` 做按位或；清除 3 就与该掩码的按位取反结果做按位与；查询 3 则检查对应位是否为 1。

位数组的大小是 `U / 64 + (U % 64 != 0)`。例如 U=130，需要 3 个 uint64_t，最后一个只使用最低 2 位。这样写也避免先计算 `U + 63` 带来的整数溢出。

**必须始终保证的条件：有效 docID 只修改自己的位；最后一个数组元素中超出有效 docID 范围的位始终为 0。**

📌 代码依据：[Bitmap](../../engineering/common/bitmap.h) 的核心接口：

```cpp
bool set(std::size_t bit) {
  if (bit >= size_) {
    return false;
  }
  words_[bit / 64] |= std::uint64_t(1) << (bit % 64);
  return true;
}

// 清除对应位；越界返回 false，即使该位原本为 0 也可成功清除。
bool reset(std::size_t bit) {
  if (bit >= size_) {
    return false;
  }
  words_[bit / 64] &= ~(std::uint64_t(1) << (bit % 64));
  return true;
}

// 范围外的编号不属于本集合，直接返回 false。
bool contains(std::size_t bit) const {
  return bit < size_ && ((words_[bit / 64] >> (bit % 64)) & 1) != 0;
}

```

这里的 `1` 必须先变成 64 位无符号值，移位量也必须小于 64。不要把复习重心放在语法上，要知道它们分别避免窄类型移位和越界移位。

### 为什么集合运算自然成立

| 业务 | 集合关系 | 对每个 uint64_t 元素执行 |
|---|---|---|
| 同时满足地域与类目 | A∩B | A & B |
| 满足任一兴趣 | A∪B | A \| B |
| 候选中去掉已删除文档 | A−B | A & ~B |

差集只保留 A 已设置的位，因此不会凭空把尾部无效位设为 1。若新增独立取反操作，则必须额外清理尾部位。

计数示例每次执行 `word &= word - 1`，删掉最低的一个 1，直到这个整数为零。实际系统可使用 popcount 指令直接统计二进制中 1 的个数，但不是掌握数据结构的前提。

## 复杂度与选择依据

设置、清除、查询 O(1)；集合运算 O(⌈U/64⌉)，示例计数 O(⌈U/64⌉＋置位数)；空间 `8×⌈U/64⌉` 字节，不含容器开销。U=1 亿约需 12.5 MB，即使集合只有 10 个成员也一样。

因此重点看内部 ID 是否连续、取值范围（值域）是否合适。稀疏的巨大业务 ID 应先映射成内部 docID，或使用排序后的文档编号列表、Roaring 压缩位图，不能直接按最大业务 ID 分配。

## 分层追问与参考答案

- **基础：为什么不能拿两个不同值域的位图随便做交集？** 需要先定义结果值域；本题显式拒绝，避免隐式截断。
- **资深：文档编号列表和位图怎样选？** 列表的空间主要取决于实际成员数，位图的空间主要取决于编号范围；还要考虑 AND 的频率、压缩与解码成本。
- **进阶：为什么 `word &= word - 1` 能计数？** 例如 `10100 - 1 = 10011`，二者按位与得到 `10000`，恰好去掉最低的一个 1；循环次数就是原有 1 的个数。
- **进阶：只有 3 个编号，最大编号接近 2³²，用普通位图合适吗？** 需要约 512 MiB，远大于保存 3 个整数的数组；可考虑下一题的分组混合表示。

## 评分与验证

基础达标需写对数组下标、位下标和交并差操作；进一步看能否解释编号范围如何影响空间、计数循环为何正确。提示“最后一个数组元素可能没有用完 64 位”后补边界记提示后完成；认为稀疏位图只占实际成员的空间属核心概念错误。本题只实现单线程基础操作。
