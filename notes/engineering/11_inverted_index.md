# 11｜最小倒排索引：把“逐文档判断”改成“按词找候选”

> 复习主线：外部 ID 映射 → 词到 docID 列表 → 列表求交 → 过滤删除 → 转回外部 ID。

## 面试题目（提供给候选人）

分词是把文本拆成词；本题直接接收分词结果，不实现分词器。输入一组已分词文档，构建最小倒排索引：为每个词记录包含它的文档编号列表，称为倒排列表（Posting List）。支持多词 AND 查询，即只返回同时包含所有查询词的文档和按外部 ID 删除。区分业务文档 ID 与内部 docID，重复词不能让结果重复。

- 建议 30 分钟；考察索引组织与查询执行，非分词算法。
- 外部 ID 为 string，内部 ID 为从 0 开始的 uint32_t；单线程追加，ID 不复用。
- 重复外部 ID 拒绝，包括已经删除的 ID；更新在第 13 题处理。
- 空查询返回空；输出按内部 docID 顺序，无相关性评分。

`add` 成功返回 true；外部 ID 重复（包括已删除的 ID）或内部编号耗尽时返回 false，原索引保持不变。这里描述的是可检查的输入错误，标准库内存分配失败不属于示例的可恢复范围。

## 面试官答案：先把两种方向的关系画出来

```text
外部文档       内部 docID      已去重 terms
ad-A          0              phone, sale
ad-B          1              phone
ad-C          2              sale

倒排：phone → [0,1]    sale → [0,2]
编号映射：0 → ad-A     1 → ad-B     2 → ad-C
live：[true, true, true]
```

查 phone AND sale 只需对 `[0,1]` 与 `[0,2]` 求交得到 `[0]`。不必再检查完全不包含这些词的文档。

**必须始终保证的条件：每加入一个文档，就为它分配一个比此前更大的 docID；同一文档的词先去重，因此各 posting 自然严格递增。**

📌 代码依据：[InvertedIndex::add](../../engineering/index/11_inverted_index.cpp)：

```cpp
const auto doc = static_cast<std::uint32_t>(external_.size());
ids_[external] = doc;
external_.push_back(external);
live_.push_back(true);
for (const auto& term : std::set<std::string>(terms.begin(), terms.end())) {
  postings_[term].push_back(doc);
}
```

### 查询过程的四步

1. 查每个词的 posting；AND 中任意词缺失，直接返回空。
2. 按 posting 长度排序，从短表开始，减少后续求交需要处理的文档数量。
3. 逐表求交，中间为空时停止。
4. 检查 live，并转换回外部 ID。

`live_[doc]` 表示文档是否有效。删除时只将它设为 false，不立刻从各个倒排列表中删除编号。这样删除操作简单，查询最后检查 live 即可排除被删文档。但这些编号仍占用空间，也可能被查询遍历；实际系统通常在合并索引段（独立构建的一部分索引）时删除这些无效记录。

## 复杂度与实现边界

每个文档有 T 个分词结果（token），去重约 O(T log T)，每个唯一词查 map 约 O(log V)，V 为词典大小；posting 追加摊销 O(1)。查询含 q 个词，查词约 O(q log V)，排序 O(q log q)，再加逐次求交成本；不能脱离 posting 长度说查询是 O(1)。

空间与不同词的数量、词与文档对应关系的数量，以及文档数成正比；删除不立即减少空间。这里是教学内存模型，不提供内存分配失败后的恢复；实际系统可以先单独构建一份尚未供查询使用的索引数据，全部成功后再让查询线程使用，避免查询读到只完成一半的数据。

本题未实现词频、位置、打分、磁盘格式和并发写入。把它们留作有意义的追问，保持代码主线清楚。

## 分层追问与参考答案

- **基础：为什么要分内部与外部 ID？** 业务 ID 可能稀疏、很长或跨段稳定；内部 ID 便于紧凑数组、位图和有序压缩，合并时可重新编号。
- **资深：短语查询还缺什么？** posting 中需要位置信息，并对齐词在同一文档中的相对位置；只有成员列表无法区分“北京到上海”与“上海到北京”。
- **资深：广告地域和状态过滤怎样接入？** 可以用属性 posting/bitmap 与文本候选求交，但需明确更新时效与过滤版本，不能只关注集合运算速度。
- **专家：删除比例升高会怎样？** 读到更多无效 posting，内存/磁盘空间增加；根据已删除文档比例、索引段大小和查询成本安排合并，同时避免后台合并抢占线上资源。

## 评分与验证

基础达标为词到列表及交集；资深达标为 docID、去重和逻辑删除；专家加分为位置索引、更新可见性与合并成本。提示“一个文档多次出现同词”后补去重记提示后完成；删除外部映射却使旧 posting 仍返回该文档是严重错误。

运行 `make run eng_inverted_index`：重复词、多词 AND、空词查询、未知词、重复删除不会改变结果、已删除 ID 不复用。若要复习完整更新链路，继续第 13 题。
