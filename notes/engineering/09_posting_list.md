# 09｜Posting List：利用有序性跳过不可能的文档

> 复习主线：列表升序且不重复，游标只向前移动；AND 找共有文档，OR 合并所有文档，差集从一个列表中排除另一个列表的文档。

## 面试题目（提供给候选人）

倒排列表（Posting List）记录包含某个词的文档编号（docID）；本题只保存编号，不包含词频和位置。给定两个升序且去重的 uint32_t docID 列表，实现交集（AND）、并集（OR）、差集（A−B）；再实现一个记录当前遍历位置、只能前进的游标 `advance(target)`，用于查找当前及后续第一个不小于 target 的文档。

- 建议 25 分钟；考察有序列表、游标的推进规则与数据分布意识。
- 空列表合法；支持 UINT32_MAX，不把这个合法编号同时用作“已经读完”的标记。
- 游标通过 bool 表示是否还有元素，只有返回 true 时才能调用 value。

`PostingCursor::value(output)` 用 bool 表示当前位置是否有效；到达末尾时返回 false，output 保持不变。先检查 advance 或 value 的返回值，再使用当前编号。

## 面试官答案：先手动比较两个列表

```text
A = [1, 4, 9]
B = [2, 4, 6, 9]
1 < 2：A 的 1 不可能再与 B 匹配，跳过
4 = 4：输出 4，两边前进
9 > 6：B 前进到 9，输出 9
```

对普通双指针 AND，较小 docID 所在侧前进，因为另一侧当前及未来值都更大；OR 每次输出最小值，相等只输出一次；差集只保留 A 中无法在 B 匹配的值。

### 为什么还要 advance

调用方不必知道倒排列表存储在数组、压缩数据块还是磁盘中，只需要“跳到不小于这个目标的位置”。它把存储细节藏在一个稳定的执行接口后面。

📌 代码依据：[PostingCursor::advance](../../engineering/common/posting.h)：

```cpp
position_ = static_cast<std::size_t>(
    std::lower_bound(docs_.begin() + position_, docs_.end(), target) -
    docs_.begin());
return position_ != docs_.size();
```

**必须始终保证的条件：游标位置只增不减；已跳过的 docID 不会成为未来结果。** target 小于当前值时停在当前值，读完列表后，后续调用仍返回 false。使用游标期间，底层列表不能被销毁，不能临时创建一个 vector 就把其游标长期保存。

### 遍历较短列表，在较长列表中查找

源码遍历元素较少的列表，对每个文档编号 x，用较长列表的调用 `advance(x)`，相等就保留。例：某冷门词只有 10 条 posting，而另一词有百万条，没必要完整扫描百万条来找到 10 个可能位置。

复杂度：最坏上界 O(s log l)，s/l 为短/长列表长度；空间 O(结果大小)。普通双指针 O(s+l) 对长度相近列表可能更好。OR 和差集使用有序合并，O(s+l)。因此“短表＋二分”不是所有分布下都更快。

## 边界与面向工程的扩展

AND 输入必须去重有序，函数本身不反复排序或校验，避免隐藏成本。NOT 需要文档全集；本题 A−B 是已有候选内的排除，不等于凭空构造全库补集。

多词 AND 可先从较短列表出发，并尽早在空结果时停止。短表长度只是成本估算的一部分，真实实现还会考虑解码块数、缓存和过滤条件能排除多少候选文档。

## 分层追问与参考答案

- **基础：为何不能每次从长表起点查找？** 因为短列表的编号递增，长列表已经跳过的部分不可能再匹配。从头查找会重复搜索这些已排除的范围，也违背了本题“游标只能向前”的要求。
- **资深：指数跳跃搜索有什么价值？** 从当前位置按 1、2、4…扩大范围，再二分；距离目标较近时不必对全部剩余范围二分。
- **资深：压缩后还能按元素二分吗？** 不能把字节偏移当元素下标；需要记录每个压缩块的最大 docID、起始字节位置，以及恢复差分所需的前一个 docID，见第 10 题。
- **专家：过滤条件按什么顺序执行？** 综合考虑检查一次需要多少时间、能排除多少文档。耗时少、能排除很多文档的条件通常先检查，但调整顺序后仍必须保证评分结果和文档版本选择正确。

## 评分与验证

基础达标为有序合并与去重；资深达标为游标只能向前推进的原因，以及长短表的处理方法；专家加分是说明压缩存储怎样支持 advance 接口。提示“游标不能后退”后修复记提示后完成；未说明排序前提或用 UINT32_MAX 同时表示合法值与结束为明显缺陷。
