# 10｜倒排表压缩：先保存相邻编号的差值，再编码

> 复习主线：对排序后的文档编号计算相邻差值，再用变长整数编码；需要跳到某一段数据时，增加记录各块位置的目录。

## 面试题目（提供给候选人）

把严格递增的 uint32_t docID 序列编码成字节数组，并能完整解码回来。差分（delta）指当前编号减去前一个编号，首项以前一个编号为 0 计算。用变长整数（varint）保存差值，每个字节有 7 位保存数值；检测截断、整数溢出和非法差分。

- 建议 25 分钟；考察编码格式、边界与随机访问取舍。
- 第一个 docID 可以为 0，后续必须严格递增；空输入对应空输出。
- 编解码返回 `CodecStatus`：成功、截断、溢出、编号不递增或读取位置无效。成功才替换输出；失败保留原输出，单整数解码也不移动读取位置。
- 不实现完整文件格式或跳表，也不要求 SIMD 解码（一条处理器指令同时解码多个值）。

## 面试官答案：压缩分成两个互不混淆的动作

```text
docID：[100, 103, 110]
delta：[100,   3,   7]
varint：每个 delta 都小于 128，各占一个字节
```

delta 没有单独压缩字节数，它只是使整数变小。varint 才把小整数用更少字节保存：每个字节最高位表示“后面还有字节”，低 7 位保存数据，由低组到高组编码。

例如 300 = 44 + 2×128，字节为 `0xAC 0x02`；第一个字节高位为 1，说明还未结束。

**必须始终保证的条件：恢复原整数时，每个字节的低 7 位都要移到对应位置，再合并到结果中；uint32_t 最多需要 5 组，最后一组最多使用低 4 位。**

📌 代码依据：[decode_varint](../../engineering/index/10_posting_compression.cpp)：

```cpp
if (i == 4 && (byte & 0xf0)) {
  return CodecStatus::kOverflow;
}
value |= std::uint32_t(byte & 127) << (7 * i);
if (!(byte & 128)) {
  pos = cursor;
  output = value;
  return CodecStatus::kOk;
}
```

重建 docID 时还要检查 `delta > UINT32_MAX - previous`，因为每个 delta 自身合法不代表累加也合法。除首项外 delta=0 会制造重复 docID，本题拒绝。

## 压缩后如何跳到指定 docID

检索中的 `advance(target)` 要找到第一个不小于 target 的 docID。为了不从头解码，可以将列表分块，并为每块记录下列信息：

```text
块目录：(块最大 docID，字节偏移，解码基值)
             ↓ 根据 target 跳过整块
命中块：读取字节 → 顺序解码小批 docID → 找到 >= target 的位置
```

跨块不能仅保存字节偏移：delta 依赖前值。可以保存块前一个 docID 作为基值，或让每块第一项存绝对 docID。每块越小，越容易只解码目标附近的数据，但需要更多目录项；每块越大，目录更少、适合批量处理，但可能顺带解码更多不需要的数据。

## 复杂度与边界

每个 uint32_t 使用 1～5 字节，编解码 O(n)，额外输出空间 O(n)。大且随机的差分可能各占 5 字节，比固定 4 字节还大，因此“压缩”不保证每个输入都缩小。

示例接受数值合法的非最短 varint 编码（例如 0 的冗余表示），只拒绝截断、超过 32 位、过长延续以及不递增 docID。若作为正式存储协议，需要另行规定是否只允许最短编码、如何校验数据完整性，以及格式版本；本例没有实现这些存储格式要求。

## 分层追问与参考答案

- **基础：为什么无序 docID 不能直接无符号相减？** 较小值减较大值在无符号计算中会得到很大的数，也破坏了列表递增的前提；先校验严格递增。
- **资深：为什么不能直接在压缩字节上二分？** 每个整数占用的字节数不同，无法从某个字节位置判断它属于哪个整数；恢复 docID 还需要累加前面的差值。
- **资深：CPU 更忙了，为什么压缩还可能变快？** 减少内存/磁盘传输和缓存占用，省下的带宽可能超过解码成本；需要在实际命中率和硬件上衡量。
- **专家：SIMD-BP128、PFor 类方法与 varint 的取舍？** 这类方法按块编码：位打包方法根据一块数据需要的位数紧凑存储；PFor 一类方法还将少量特别大的值单独保存。它们适合批量解码，但需要处理特殊大值和不足一块的末尾数据。追问重点是这种取舍，不要求记住库名或处理器指令。

## 评分与验证
