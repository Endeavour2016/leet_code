# 动态规划与贪心

## 动态规划：记录重复子问题

DP 的核心不是填表，而是定义状态。四步法：

1. `dp[i]` 或 `dp[i][j]` 表示什么。
2. 最后一步从哪些更小状态转移而来。
3. 初始化哪些最小问题。
4. 按依赖顺序遍历并决定最终答案位置。

```mermaid
flowchart LR
  A[定义状态] --> B[写转移方程]
  B --> C[初始化]
  C --> D[确定遍历顺序]
  D --> E[空间优化]
```

通用一维模板：

```cpp
vector<int> dp(n, initial);
for (int i = 1; i < n; ++i) {
  dp[i] = best(dp[i - 1], transition(i));
}
```

股票只能交易一次时，“截至今天的最低买入价”就是压缩后的历史状态；已验证实现：[121_best_time_to_buy_and_sell_stock.cpp](../DP/121_best_time_to_buy_and_sell_stock.cpp#L14-L34)。

## 背包遍历顺序

- 0/1 背包：容量倒序，避免同一件物品在一轮中重复使用。
- 完全背包：容量正序，允许重复使用当前物品。
- 求组合数与求排列数的循环顺序不同，必须从状态语义推导，不能死背。

## 贪心：证明局部选择不损失最优解

贪心适用时，每一步只保留对未来最有利的状态。判断标准不是“看起来最优”，而是能用交换论证或覆盖范围证明：替换为当前选择不会让全局答案变差。

股票可多次交易时，所有正的相邻差值都可以收入囊中：[122_best_time_to_buy_and_sell_stock_ii.cpp](../DP/122_best_time_to_buy_and_sell_stock_ii.cpp#L13-L30)。这等价于把一段连续上涨拆成若干天收益：

```text
1 -> 3 -> 5
整体收益 5-1 = 4
逐日收益 (3-1) + (5-3) = 4
```

## DP 与贪心的区别

| 问题 | DP | 贪心 |
|---|---|---|
| 保留状态 | 多个可能有用的历史状态 | 一个被证明足够的最优状态 |
| 正确性来源 | 状态覆盖所有选择 | 局部选择可安全替换 |
| 常见代价 | 时间/空间较高 | 通常更低，但证明更难 |

## 易错点

- 状态定义含糊，导致转移式“凭感觉”。
- 初始化与状态语义不一致。
- 原地压缩后遍历方向错误。
- 把“局部看起来最大”误当作贪心证明。
